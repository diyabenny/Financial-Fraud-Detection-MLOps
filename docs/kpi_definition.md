# 1.4 KPI Definition

## 1.4.1 Purpose

This document defines the key performance indicators (KPIs)
that will be used to evaluate the financial fraud detection
model.

The dataset contains a highly imbalanced target distribution,
with fraudulent transactions representing approximately 0.60%
of all transactions. Therefore, overall accuracy alone is not
sufficient to assess model performance.

The evaluation will focus primarily on fraud-sensitive metrics
that measure the model's ability to detect fraudulent
transactions while controlling false fraud alerts.

For KPI calculations, fraudulent transactions (`TX_FRAUD = 1`)
are treated as the positive class, while legitimate transactions
(`TX_FRAUD = 0`) are treated as the negative class.

---

## 1.4.2 Precision

Precision measures the proportion of transactions predicted as
fraudulent that are actually fraudulent.

Precision = TP / (TP + FP)

Precision is important because false positives represent
legitimate transactions that are incorrectly flagged as
fraudulent.

A higher precision indicates that a larger proportion of fraud
alerts generated by the model are actually fraudulent.

Precision will therefore be monitored to assess the quality of
fraud alerts and the proportion of legitimate transactions that
are incorrectly flagged.

---

## 1.4.3 Recall

Recall measures the proportion of actual fraudulent transactions
that are correctly identified by the model.

Recall = TP / (TP + FN)

Recall is the primary business KPI for this project because false
negatives represent fraudulent transactions that are incorrectly
classified as legitimate.

A higher recall indicates that the model is detecting a larger
proportion of actual fraudulent transactions.

Recall therefore directly reflects the project's primary business
priority of reducing missed fraudulent transactions.

---

## 1.4.4 F1-Score

The F1-score is the harmonic mean of precision and recall.

F1 = 2 × (Precision × Recall) / (Precision + Recall)

The F1-score provides a balanced measure of precision and recall.

It is useful for this project because the fraud detection system
needs to identify fraudulent transactions while also controlling
the number of legitimate transactions incorrectly flagged as
fraudulent.

F1-score will be used as a supporting KPI when comparing model
performance.

---

## 1.4.5 PR-AUC

Precision-Recall Area Under the Curve (PR-AUC) summarizes the
precision-recall trade-off across different classification
thresholds by measuring the area under the precision-recall
curve.

PR-AUC is particularly relevant to this project because the
fraudulent class is highly underrepresented, accounting for
approximately 0.60% of the dataset.

PR-AUC will be used as the primary model evaluation KPI for
assessing performance on the minority fraud class across
different classification thresholds.

---

## 1.4.6 ROC-AUC

ROC-AUC measures the model's ability to distinguish between
legitimate and fraudulent transactions across different
classification thresholds.

ROC-AUC will be reported as a supporting evaluation metric.

Because the dataset is highly imbalanced, ROC-AUC will not be
used as the sole indicator of fraud detection performance.

---

## 1.4.7 Accuracy

Accuracy measures the proportion of all transactions that are
classified correctly.

Accuracy = (TP + TN) / (TP + TN + FP + FN)

Accuracy will be reported as a reference metric but will not
be treated as a primary KPI.

This is because the dataset contains approximately 99.40%
legitimate transactions and only 0.60% fraudulent transactions.
A model could achieve high accuracy by predicting most
transactions as legitimate while still failing to detect a
large proportion of fraudulent transactions.

---

## 1.4.8 False Positive Rate (FPR)

False Positive Rate (FPR) measures the proportion of legitimate
transactions that are incorrectly classified as fraudulent.

FPR = FP / (FP + TN)

FPR is relevant to the project's business objective of reducing
unnecessary fraud alerts.

A lower FPR indicates that fewer legitimate transactions are
incorrectly flagged as fraudulent.

FPR will be used as a supporting KPI to assess the level of
false alerts generated by the fraud detection model.

---

## 1.4.9 KPI Priority

The KPIs will be prioritized according to the business
requirements and characteristics of the dataset.

| Priority | KPI | Role |
|---|---|---|
| Primary Business KPI | Recall | Measure the ability to detect actual fraudulent transactions |
| Primary Model KPI | PR-AUC | Evaluate minority-class performance across classification thresholds |
| Supporting | Precision | Assess the quality of fraud alerts |
| Supporting | FPR | Measure the proportion of legitimate transactions incorrectly flagged |
| Supporting | F1-Score | Balance precision and recall |
| Supporting | ROC-AUC | Measure overall class discrimination |
| Reference | Accuracy | Provide overall classification performance |

Recall is treated as the primary business KPI because the
business objective places particular importance on detecting
actual fraudulent transactions and reducing missed fraud.

PR-AUC is treated as the primary model evaluation KPI because
the dataset is highly imbalanced and PR-AUC provides a useful
measure of minority-class performance across different
classification thresholds.

Precision and FPR will also be considered to ensure that
improvements in fraud detection do not result in an impractical
level of false fraud alerts.

F1-score and ROC-AUC will provide additional supporting
information, while accuracy will be reported only as a reference
metric.

---

## 1.4.10 Classification Threshold

The model will produce a fraud probability or score that can be
converted into a legitimate or fraudulent prediction using a
classification threshold.

The default threshold should not automatically be assumed to be
optimal for this fraud detection problem because the dataset is
highly imbalanced and the business must balance fraud detection
against unnecessary fraud alerts.

The operating classification threshold will therefore be
evaluated and selected during model development based on the
project's fraud-detection and false-alert objectives.

Threshold selection will be performed using appropriate
validation data and will not be determined using the test set.

No fixed numerical performance target or classification
threshold is established at this stage. Quantitative targets
will only be introduced if they are supported by project or
business requirements during later development.

---

## 1.4.11 System-Level KPIs

As the project progresses toward a production-oriented MLOps
system, operational KPIs will also be considered.

These include:

- Prediction latency
- Prediction throughput
- System availability
- Data drift
- Model drift
- Model performance degradation

These KPIs will be implemented and monitored during the later
MLOps stages of the project.

---

## 1.4.12 Baseline Evaluation Criteria

The initial baseline model will be evaluated using the following
metrics:

- Precision
- Recall
- F1-Score
- PR-AUC
- ROC-AUC
- Accuracy
- False Positive Rate (FPR)

The baseline results will provide a reference point for
evaluating improvements from more advanced models developed
during later stages.

Particular attention will be given to recall and PR-AUC because
of the severe class imbalance and the business importance of
detecting fraudulent transactions.

Precision and FPR will also be considered to ensure that fraud
detection performance is not achieved at the cost of excessive
false fraud alerts.

F1-score and ROC-AUC will provide additional supporting
evaluation measures, while accuracy will be used as a reference
metric.

The baseline evaluation will use a fixed evaluation procedure so
that later models can be compared fairly against the baseline.
